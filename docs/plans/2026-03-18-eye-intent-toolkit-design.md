# Eye Intent Toolkit Design

## Goal

这个项目的目标不是一次性做完完整研究平台，而是构建一个足够像“真实产品骨架”的 Python 工具包：既能让面试官快速看到你对眼动数据处理、意图识别、人因建模、多模态融合和工程化封装的理解，也能为后续继续扩展深度模型、在线流处理和交互式仪表板保留稳定接口。

## MVP 架构

MVP 采用分层设计。`io` 层负责把不同厂商导出格式归一成标准列名；`preprocess` 和 `events` 层完成缺失值处理、平滑滤波、坐标归一化和 I-VT 事件检测；`features` 层输出可直接进入机器学习模型的统计与行为特征；`modeling` 层封装分类/回归训练、指标评估和解释接口；`multimodal` 与 `streaming` 层提供时间对齐和滑动窗口在线推理；`visualization` 层用于生成适合作品集展示的图表；`pipeline` 与 `cli` 则把这些能力串起来，形成更像“产品”而不是“脚本集合”的使用体验。

## 关键设计选择

优先选择 `numpy + pandas + scikit-learn + matplotlib + PyYAML` 作为默认依赖，这样项目既轻量又容易安装。像 `.edf` 解析、SHAP/LIME、深度模型和 Dashboard 都通过可选依赖扩展，而不是把整个工具包做成重型研究环境。这样能兼顾可运行性和专业感。事件检测先落地一个稳定的 I-VT 版本，复杂事件和更精细的角速度模型后续扩展。建模层先给出随机森林、SVM、梯度提升等强基线，同时保留注册机制，未来接入 LSTM、TCN、Transformer 时不需要改动上层 API。

## 作品集价值

从招聘视角看，这个项目能同时展示三类能力：第一，眼动与人因数据理解；第二，AI 建模和特征工程能力；第三，软件工程成熟度。面试官不只是看到“我会做模型”，而是能看到你把数据容器、扩展点、CLI、测试、配置、示例和可视化全部组织成了一个可复用工具包。这一点对于“AI 驱动人因应用经验”会非常加分。
